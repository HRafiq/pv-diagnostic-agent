# CLAUDE.md — working rules for this repository

A PV plant diagnostic agent. Read `README.md` for what it does and
`docs/DECISION.md` for why it is built the way it is.

---

## The rules

These are not style preferences. Each one exists because breaking it silently
destroys the thing the project is trying to measure.

### Evaluation integrity

- **Never inject faults at the signature level — physics only.** A string fault
  zeroes a fraction of DC current on one MPPT with a realistic transition and
  noise. It never "reduces PR by 0.12". The diagnostic logic must *rediscover*
  the signature, or the evaluation is measuring "does my rule match my
  generator".
- **The simulator and the expectation model must never share a configuration.**
  If the synthetic plant is generated by pvlib and `compute_expected_output()`
  is the same pvlib ModelChain with the same parameters, every injected deficit
  is trivially detectable and accuracy is meaningless. Simulate with the
  detailed stack (SAPM/CEC + full loss tree + sensor noise + parameter offsets);
  form expectations with the coarser one (PVWatts + Faiman). Prefer injecting
  onto *real measured* series wherever the tool set allows it.
- **Never tune against the held-back set.** Report tuning and held-back results
  separately, always. A gap over 0.10 means overfitting and gets said out loud.

### Architecture

- **Never add a tool that returns a fault classification.** Tools take
  measurements. `compute_pr`, `characterize_onset`, `per_mppt_current_balance`
  — yes. `classify_fault` — no. The diagnosis is the agent's job; if it happens
  inside one function, this is a rules engine with a chat wrapper.
- **Never put an LLM call inside a tool function.** Tools are pure, deterministic
  functions with validated Pydantic args and structured outputs. Strategy and
  interpretation belong to the agent; arithmetic and thresholds do not.
- **No LLM in arithmetic, thresholds, scoring, or data scope.**
- **Never let the dashboard reimplement a computation that exists in `src/`.**
  A chart showing PR calls `physics.compute_pr()` — the same function the tool
  node calls. This is what guarantees the dashboard and the agent cannot
  diverge. `src/` is UI-agnostic; the dashboard is a thin caller.
- **Never call `datetime.now()`, `date.today()`, `time.time()`, or
  `pd.Timestamp.now()` anywhere in `src/`.** Use the injected `Clock`. There is
  no real-time public PV feed, so "now" is a replay clock over historical data,
  and every Watcher trigger and "what's new since yesterday" depends on it.
  A test enforces this by scanning the source tree.

### Honesty of output

- **Never let the critic return unstructured prose.** `CriticVerdict` only.
  A critic that returns "looks good" is worse than no critic.
- **Never show a cause or a confidence on an unsettled finding.** If the
  investigation could not separate array soiling from sensor soiling, the
  finding must not say "soiling, confidence 0.78" — that is the exact bug that
  dispatches a wash crew to a clean array. `Finding` validators enforce this;
  do not weaken them.
- **`not_enough_evidence` is a first-class successful outcome**, not a failure
  path. An agent that always commits is broken.
- **Always record `was_planned` on every tool call**, with
  `reason_for_choosing` whenever it is `False`. This is what makes agency
  visible in the interface and measurable in the eval harness.

### Interface language

- **Never show ML jargon in the UI.** Internal code and `docs/` may use precise
  technical terms. The dashboard may not.

  | Never show      | Show instead                |
  | --------------- | --------------------------- |
  | abstention      | not enough evidence         |
  | confounder      | look-alike                  |
  | groundedness    | claims backed by a source   |
  | recall@10       | right document in top 10    |
  | dev / holdout   | tuning set / held back      |
  | hypothesis      | possible cause              |
  | macro-F1        | overall accuracy            |

### Repository hygiene

- **Never commit corpus PDFs, traces, or data files.** Ingest scripts download
  into gitignored directories; a manifest with SHA-256 checksums is committed
  so the dataset is reproducible without shipping it.
- **`docs/DECISION.md` is append-only.** Every non-obvious choice gets a dated
  entry with the alternatives considered.
- **Always stop at a gate and wait for review.** Do not batch steps.

## Determinism — what is and is not guaranteed

The handoff specified "LLM temperature 0". **That parameter no longer exists**
on current Claude models: `temperature`, `top_p`, and `top_k` were removed on
Claude Opus 5 / Sonnet 5 / Opus 4.7 / Opus 4.8 and return a 400 error. Reasoning
depth is steered with `output_config.effort` and prompting instead.

So the determinism claim is scoped:

| Layer                              | Guarantee                                          |
| ---------------------------------- | -------------------------------------------------- |
| Physics, detectors, tools          | Bitwise identical for the same seed and input      |
| Fault injection                    | Bitwise identical for the same seed                |
| Retrieval (BM25 + dense + rerank)  | Identical for a fixed corpus snapshot hash         |
| LLM planner / router / synth / critic | **Not deterministic.** Never claim it is.       |

For regression runs, LLM responses are cached by `(model, prompt_hash)` so a
re-run compares like with like. Headline eval metrics are reported as mean ±
spread over N=3 fresh runs, never as a single number.

## Layout

```
src/          UI-agnostic core. Everything the agent and the dashboard share.
  clock.py      The ONLY time source.
  determinism.py Seeding and run-scoped RNG.
  config.py     Typed loaders for config/*.yaml.
  trace/        TraceStep model + JSONL writer (the dashboard's data source).
  findings/     Finding model, lifecycle, ranking.
  agent/        State, nodes, plain loop (step 4), LangGraph port (step 12).
  physics/ data/ detect/ tools/ rag/ knowledge/ baseline/ analyses/ viz/
simulator/    Physics-level fault injector.
eval/         Runner, metrics, agency metrics, golden sets.
dashboard/    FastAPI + Jinja2 + Alpine.js + Plotly.js. Thin; calls src/ only.
watcher.py    CLI that advances the clock, sweeps, and writes findings.
```

## Conventions

- Python 3.11, pinned dependencies, `ruff` + `mypy`.
- All times are timezone-aware UTC internally; site-local only at the edges.
- Irradiance in W/m², energy in kWh, power in kW, temperature in °C. Units go in
  the field name when there is any doubt (`energy_at_stake_kwh`).
- Pydantic v2 models for every boundary: tool args, tool results, state, traces.
